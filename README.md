# 地下城探险 · Dungeon Delve

Python 课程大作业：一个用 **纯 Python + tkinter** 实现的回合制地牢探险 Roguelike。
程序化生成地图、回合制策略战斗、精英与治疗兵种、难度曲线剖面、JSON 存档、
matplotlib 数据可视化统计。

> 版本变化见 [`CHANGELOG.md`](CHANGELOG.md)。

---

## 快速开始
```bash
# 0) 克隆仓库
git clone https://github.com/Physi11/python_game.git
cd python_game

# 1) 安装依赖（只有图表功能需要，游戏本体仅依赖标准库）
pip install -r requirements.txt

# 2) 启动游戏
python main.py
```

Windows 用户也可以直接双击 `run.bat`。

> **注意**：本项目需要带 `tkinter` 的 Python。若启动时报"缺少 tkinter"，
> 请改用官方版 Python（安装时勾选 tcl/tk）运行，例如 `D:\python\python.exe main.py`。

## 玩法

你是踏入地下城的冒险者，目标是下到 **第 10 层** 击败 **深渊领主**。

**战斗是回合制策略制**：每回合只能做一个行动——移动一格、攻击、或原地等待。

- **攻击要先装备武器**：近战（剑 / 骨矛 / 巨刃）与远程（短弓 / 长弓）各占一个槽，按 `Tab` 切换
- **只有更强的武器才能替换现有武器**：同攻击或更弱会被拒绝，避免误操作把 +3 的剑换成白板
- **用鼠标选定目标区域**：右键或 `F` 进入瞄准，悬停时用**蓝色**画出这一击会覆盖的格子，左键确认
- **敌人会蓄力预告**：起手时把即将打击的区域**锁定**并逐只上色（红/橙/品红/紫/青绿），
  每片范围有同色描边，敌人格子右上角显示"还剩几回合出手"；锁定后区域不再跟着你走，
  **走出去就能躲掉**
- 越重的武器伤害越高、蓄力越久：巨刃 +9 但要花一回合抬起，铁剑 +2 可以立刻挥出
- **同名装备自动合成升级**：捡到同款武器/护甲会合成（最高 +3），攻击/防御 +1，重复掉落不占背包
- **精英怪**：金色描边的强化个体，血更厚、伤害更高、奖励翻倍，蓄力方式与同族一致
- **治疗怪（萨满巫医）**：青绿描边的支援单位，每回合给最虚弱的同伴回血，不会攻击玩家——
  放着不管会让你的输出被抵消，必须先点掉它
- **四类趣味房间**：治疗泉（回 28% 生命）、宝库（满地道具 + 两名守卫）、
  陷阱房（扣 12% 当前生命换一件好装备）、力量祭坛（献祭 15% 当前生命换永久 +2 攻击）
- 地图有战争迷雾；每层至少有一瓶治疗药水；进入第 10 层会回满生命
- 死亡、通关或超时都会自动把本局数据写入 `data/records.json`

## 快捷键

| `I` | 打开 / 关闭背包 |
| `>` | 站在楼梯上时进入下一层 |

| `F9` / `Ctrl+O` | 读取 1 号存档槽 |

## 版本控制与自动同步

### 仓库约定

`.gitignore` 已经排除掉"不该进版本库"的三类东西：

| 排除项 | 原因 |
|---|---|
| `__pycache__/`、`*.pyc` | 字节码，每台机器都不一样 |
| `data/saves/*.json`、`data/records.json` | 存档与战绩是**本机运行时状态**，会随每次游玩变化 |
| `.workbuddy/`、`*.log`、`*.tmp`、`docs/report_preview/` | 本机工作数据与临时产物 |

> 图表 `data/charts/*.png`、报告 `docs/*.docx`、截图 `docs/screenshots/*.png`
> 是**交付物**，正常提交。仓库总大小约 3.5 MB，不需要 Git LFS。

### 提交信息规范

完整规则见 [`docs/COMMIT_CONVENTION.md`](docs/COMMIT_CONVENTION.md)，核心是 Conventional Commits：

```
<类型>(<范围>): <一句话说明>

<正文：改了什么、为什么改>
```

类型用 `feat` / `fix` / `refactor` / `perf` / `test` / `docs` / `style` / `build` / `chore`，
范围用模块名（`dungeon`、`ui`、`tools`、`tests`、`docs`、`assets`）。

### 首次关联远程仓库

```bash
# 1) 登录 GitHub（只需一次，会打开浏览器）
gh auth login

# 2) 关联远程仓库
git remote add origin https://github.com/<你的用户名>/<仓库名>.git

# 3) 首次推送并建立上游关联
git push -u origin main
```

登录后 `gh` 会自动配好 git 的凭据助手，之后 `git push` 不再需要输密码。

### 自动提交推送

```bash
python tools/auto_sync.py                # 常驻监听，Ctrl+C 退出
python tools/auto_sync.py --once         # 只同步一次（适合定时任务）
python tools/auto_sync.py --dry-run      # 只打印将要提交的内容，不落盘
python tools/auto_sync.py --note "修了什么"   # 给这次提交写一句目的
```

Windows 下直接双击 **`auto_sync.bat`** 即可常驻。

工作方式：每 3 秒看一眼 `git status`，一旦发现改动，**等它静默 20 秒**
（避免改一个函数就提交一次）再 `add → commit → push`。用 `git status` 而不是
自己遍历文件，是为了自动遵守 `.gitignore`，也能正确处理删除、重命名和二进制文件。

自动生成的提交长这样：

```
chore(sync): 同步 3 个文件（ui、tools）

改动明细：
- 修改  ui/app.py            +12 -4
- 新增  tools/auto_sync.py   +168 -0
- 删除  data/saves/old.json  -3 -0

涉及模块：ui、tools
合计：3 个文件，+177 -4
目的：把焦点回收逻辑抽成 _focus_map()
```

**想让自动提交也带上"为什么改"**，有两种方式（都不需要改代码）：

1. 启动时加 `--note "..."`，这条说明只用于**下一次**提交；
2. 在项目根目录放一个 `SYNC_NOTE.txt` 写上目的，脚本会在提交时读走并删除它，
   适合"边写代码边记一笔"的场景。

监听日志写在 `.git/auto_sync.log`（在 `.git` 内部，不会被提交）。

## 图标资源替换

地图上的玩家、怪物、道具、楼梯、门都支持换成自己的图片，**不需要改任何代码**。

### 三步替换

1. 准备一张 **24 × 24 像素、带透明通道的 PNG**（尺寸不符也能用，程序会自动缩放；
   但没有透明通道的话会带一个白底方块）。
2. 按 `assets/icons.json` 里登记的路径放进去，例如
   `assets/icons/player.png`、`assets/icons/monster/goblin.png`。
3. 回到游戏按 **F12**（或菜单「查看 → 重载图标资源」），立即生效，不用重启。

删掉某个 PNG，对应图标就自动回退成原来的字符（`@`、`g`、`/`、`↓`…），
所以**整个 `assets/icons/` 是空的也不影响运行**，开箱就是纯字符外观。

### 清单文件的结构

`assets/icons.json` 是唯一需要关心的配置文件：

```json
{
  "version": 1,
  "base_dir": "assets/icons",
  "entries": {
    "player":          { "label": "玩家",     "file": "player.png" },
    "monster.goblin":  { "label": "哥布林",   "file": "monster/goblin.png" },
    "monster":         { "label": "怪物通用", "file": "monster/_default.png" },
    "item.potion":     { "label": "药水通用", "file": "item/potion.png" },
    "stair":           { "label": "下行楼梯", "file": "object/stairs.png" }
  }
}
```

| 字段 | 说明 |
|---|---|
| `version` | 清单格式版本，目前只接受 `1` |
| `base_dir` | 图片根目录，相对项目根；也可以用绝对路径 |
| `entries.<键>.file` | 相对 `base_dir` 的 PNG 路径。**必须是相对路径且以 `.png` 结尾**，否则该条被忽略 |
| `entries.<键>.label` | 中文名，只用于文档与提示，不影响渲染 |

### 三级回退

某个格子要画图标时，按下面的顺序找第一个存在的文件：

| 格子 | 查找顺序 |
|---|---|
| 玩家 | `player` |
| 怪物 | `monster.<种类>` → `monster` |
| 道具 | `item.<道具名>` → `item.<类别>` → `item` |
| 楼梯 / 门 | `stair` / `door` |

所以只画一张 `item/potion.png` 就能覆盖全部药水；想给「符文长剑」单独做图，
就再放一张 `item/sword_rune.png` 即可覆盖。

### 素材来源与着色

仓库里自带的 19 张图标来自 [game-icons.net](https://game-icons.net/)，许可为
**CC BY 3.0**，逐图作者署名见 [`assets/icons/CREDITS.md`](assets/icons/CREDITS.md)。
分发时请一并保留该文件。

下载下来的是**纯白剪影**，游戏在加载时按 `icons.json` 里每条记录的 `tint` 字段
做"白 × 颜色"上色，所以同一份素材能同时当红色怪物、青色玩家、金色道具，
不必为每种颜色各存一份图。

### 为什么墙和地板不做成图片

墙和地板承担着战争迷雾的三态显示（未探索 / 已探索 / 当前可见），现在只改
一个填充色就能完成；换成图片后每层 1000 个格子都要切换贴图，还要为迷雾再准备
一套压暗版本，收益几乎为零。楼梯、门属于"物件"，所以支持。

### 想要一套空白素材

```bash
python tools/export_icon_slots.py
```

按清单把所有条目渲染成 24×24 占位 PNG（透明底 + 当前字符），之后直接在这些文件上
改画。想恢复纯字符外观，把生成的 PNG 删掉即可。

## 难度曲线

不是"每层 +3 只怪"的直线，而是**有峰有谷的锯齿**。下面先说依据，再说落地。

### 三条依据

1. **心流与"张弛"（Csikszentmihalyi, 1990；Schell《The Art of Game Design》第 9 章）**
   挑战低于能力会无聊、高于能力会焦虑，中间那条窄带才是心流。Schell 进一步指出：
   在通道内**锯齿前进**比直线爬升更有趣——"太多紧张会疲惫，太多放松会无聊"（*too much
   tension, and we wear out. Too much relaxation, and we grow bored*）。
   → 落地：每个尖峰层之后紧跟一个**释放层**，并给一个恢复房间。

2. **兴趣曲线的释放节拍（Schell 的 interest curve）**
   健康曲线的形状是"上升 → 尖峰 → 快速释放 → 更高的下一个尖峰"，且释放的时长要与
   前面的峰值成比例。
   → 落地：3/7/9 层是尖峰（12/20/20 只 + 精英），4/8 层是释放（9/14 只 + 治疗泉）。

3. **动态难度必须克制（Hunicke, 2005, *The Case for Dynamic Difficulty Adjustment
   in Games*, ACE '05, pp.429–433；Adams, *The Designer's Notebook*）**
   Hunicke 的结论是 DDA 要"在不破坏核心体验的前提下"调整；Adams 补充三条工程约束：
   只增强对手、不要削弱玩家；小步频繁而非一次大变；并且应当**可关闭**。
   → 落地：自适应只在 ±2 只小怪范围内微调，永不改玩家数值，且在设置里可关。

### 逐层剖面

| 层 | 怪物 | 精英 | 房间 | 角色 |
|---|---|---|---|---|
| 1 | 5 | 0 | 治疗泉 | 钩子：低压力教学 |
| 2 | 8 | 0 | — | 建立：引入弓兵 |
| 3 | 12 | 1 | 陷阱房 | **第一个尖峰** |
| 4 | 9 | 0 | 治疗泉 | 释放 |
| 5 | 13 | 0 | 力量祭坛 | 攀升 |
| 6 | 16 | 1 | — | 加压 |
| 7 | 20 | 2 | 宝库 | **高峰：风险回报** |
| 8 | 14 | 0 | 治疗泉 | 释放：为决战蓄力 |
| 9 | 20 | 2 | 力量祭坛 | **决战前夜** |
| 10 | 6 + Boss | 0 | — | 高潮 |

这张表由 `config.FLOOR_PROFILE` 定义，`test_curve_is_not_monotonic` 会检查它
**确实不是单调递增**（至少两处回落），`test_each_spike_has_a_release_room`
会检查每个尖峰后面都跟了恢复房间——把设计意图写成了断言，改坏了测试会红。

### 难度预设与自适应

- **预设**（设置里可选）：轻松 0.75× 怪量 / 无精英 / 0.85× 血；标准 1.0×；硬核 1.2× / 1.6× 精英 / 1.1× 血。
  只改对手，不动玩家。
- **自适应**（默认开）：玩家血量 ≥80% 且击杀效率高 → 下一层多 2 只；血量 ≤35% → 少 2 只。
  上限 ±2，绝不改变层与层之间的锯齿结构，所以玩家察觉不到"游戏在放水"。
- 两者都只在**新的一层**生效，不会在层中途重roll地图。

### 实测

80 局批量自动对局（两组各 40 局，种子 5000–5039 / 6000–6039；机器人有完美信息、
会走位躲蓄力、优先点治疗怪）：

| 指标 | 数值 |
|---|---|
| 通关率 | 41.3%（33/80；两组分别为 37.5% 与 45.0%） |
| 平均到达层数 | 8.28 |
| 平均回合 | 1888 |

与改造前（47.5%）基本持平，说明加入精英、治疗怪与房间后曲线被重新配平。
机器人比人类强得多（不会误操作、能精确计算红框），所以 41% 已经是
"人类玩家偏难、但可通关"的位置。单组 40 局的 95% 置信区间约 ±15 个百分点，
两组差异属于正常抽样波动，不需要为此再调数值。

## 开始界面与设置

启动后先看到开始界面：**开始新游戏 / 读取存档 / 设置 / 退出**。开始界面期间菜单栏会被
隐藏、游戏按键被屏蔽，避免"在菜单里按方向键，后面那局游戏偷偷走了几步"。

设置面板**完全由 schema 生成**（`ui/settings.py` 的 `SETTING_SPECS`）：

```python
SETTING_SPECS = (
    SettingSpec(key="fullscreen", label="全屏模式", kind="bool", default=False),
    SettingSpec(key="adaptive_difficulty", label="自适应难度", kind="bool", default=True),
    SettingSpec(key="difficulty", label="难度预设", kind="choice", default="normal",
                choices=(("easy", "轻松"), ("normal", "标准"), ("hard", "硬核"))),
)
```

**新增一个设置项 = 往这个元组里追加一条**：面板自动多一行、自动读写、
自动持久化到 `data/settings.json`，不需要改任何界面代码。这就是"预留扩展通道"。

- 全屏也可以按 `F11` 随时切换，选择会被记住；
- 配置文件损坏/字段类型不对时一律回退默认值，不会把游戏挡在启动界面之外；
- 旧版本写的配置里若有当前版本不认识的键，会被原样保留，方便来回切版本。

## 设计说明

### 为什么逻辑层不碰 tkinter

`dungeon/` 目录严禁导入任何界面库，这条约定由 `tests/test_architecture.py`
自动扫描源码来保证。收益有三点：

1. 单元测试不需要显示器，153 个用例 0.35 秒跑完；
2. `tools/balance_sim.py` 能在没有界面的环境里跑上百分局验证数值；
3. 将来把界面换成网页或终端，业务代码一行都不用改。

### 为什么要专门做"焦点回收"

Tk 的 `listbox.tcl` 与 `text.tcl` 在鼠标按下时会无条件执行 `focus $w`，
`-takefocus 0` 拦不住（它只影响 Tab 遍历）。焦点一旦停在右侧背包列表或底部日志上，
主窗口的 `<Key>` 绑定虽然仍会触发，却会被"文本控件不处理按键"的守卫挡掉——
表现为方向键不动、`I` 打不开背包、`>` 下不了楼。

因此本项目做了三件事：

1. 守卫从"控件黑名单"细化成"控件 + 按键白名单"——列表只独占它真正会消费的
   方向键、空格等，其余按键照常交给游戏；
2. 在使用道具后、点击地图后、关闭弹窗后、按 `Esc` 时主动把焦点还给地图画布；
3. 点击日志区后用 `after_idle` 延迟一拍回收焦点，不打断日志自身的定位。

`ui/dialogs.py` 的 `<Destroy>` 钩子还必须用 `event.widget is win` 过滤，
因为 Tk 会为每个子控件各触发一次销毁事件；同时要吞掉 `TclError`，
否则主窗口退出时控制台会冒 traceback。

### 倒计时为什么画在格子里面

24px 的格子没有多余空间。早先把"还剩几回合出手"的徽章画在 `y*TILE - 6`，
等于骑在格子上沿——敌人贴着墙站时上半截压在墙上，看起来就像被墙吃掉一半。
现在徽章整个收进敌人自己格子的**右上角**（`BADGE_W/H` 都小于 `TILE`，
坐标贴整数边界），无论上下左右是什么地形都不会越界，也不会被后创建的图元
盖住（`refresh()` 末尾统一 `tag_raise("badge")`）。

### 敌人多了怎么分清哪片范围是谁的

只用一层红色半透明填充时，两三只敌人一起蓄力就糊成一片。现在：

1. **配色**：按出现顺序给每只敌人分配一种威胁色（`theme.THREAT_PALETTE`，
   红/橙/品红/紫/青绿，刻意避开玩家瞄准的蓝色与自蓄力的金色）；
2. **描边**：每片区域沿外轮廓画同色实线（`_outline_segments` 用集合对称差
   抵消共享边），两片相邻时自然出现分界线，重叠格也能靠两条不同颜色的边看出归属；
3. **同色徽章**：右上角数字的边框与它那片范围同色，数字本身固定白色保证可读。

颜色按 `id(monster)` 记忆，被打死才释放色位——用列表下标当键的话，
一只怪死掉会让剩下的全部换色。

### 装备合成为什么放在拾取时

`Player.pick_up` 里先尝试合成、再检查背包容量：背包满了也能把同款装备合进
身上那件，否则"捡不起来"和"能升级"会互相打架。规则是同名即可合成、
等级取较高者 +1，候选优先身上穿着的（这样第二把铁剑立刻转化成攻击力），
上限 +3——让"铁剑 +3（+5）"落在符文长剑（+4）与深渊之刃（+7）之间，
不至于靠堆数量反超深层装备。

存档只记 `upgrade` 等级，读档时用 `restore_upgrade` 重放并截断到上限；
即使把存档改成 `upgrade: 99`，最多也只能拿到 +3。加成是"基础值 + 每级增量"
重算出来的，不直接存最终攻击力，顺带封死了手改存档造神装的路。

### 为什么"近战换装不显示"值得单独写一段

这是两个概念被混用造成的：`Weapon.slot` 是**武器分类**（`melee` / `ranged`），
而 `Player.equipment` 的键是**装备槽**（`weapon` / `ranged` / `armor`）。
`equip()` 图省事直接把 `slot` 当字典键写入，于是近战武器落进了
`equipment["melee"]` 这个凭空出现的键：

- 右侧面板读 `equipment["weapon"]` → 还是旧武器，看起来"换了没反应"；
- 战斗计算 `attack_power(equipment["weapon"])` → 也还是旧武器，**实际伤害没变**。

更隐蔽的是"已经装备着"的判重也一起失效了（`equipment.get("melee")` 永远 None），
所以可以反复"装备"同一把剑。

修法是给 `Weapon` 增加唯一出口 `equip_slot` 属性，`equip()`、自动合成、
批量模拟器的换装判断全部走它。**同一个概念只允许一个映射函数**，这是这次最实际的教训。

### 换装为什么要有"只许更强"的门槛

`Weapon.apply` 原先只要 key 不同就替换。背包里翻找道具时很容易点到一把白板铁剑，
把辛苦合成到 +3 的武器顶掉，而且**没有任何提示**。

现在的比较规则是分层的（`Weapon.is_stronger_than`）：

1. 攻击加成严格更高 → 更强；
2. 攻击相同，看蓄力：不需要蓄力的更强（即时出手比抬起一回合灵活）；
3. 再相同，看射程：更远的更强。

用"含强化加成的攻击力"而不是原始值，才能正确处理"铁剑 +3（+5）不该被
白板符文长剑（+5）换掉"这种情形。护甲同理（只比防御）。

配套地把武器阶梯重新排成单调的：铁剑 +2（1 层）→ 骨矛 +3（2 层）→
符文长剑 +5（4 层）→ 深渊之刃 +7（7 层）→ 巨刃 +9（8 层）。
原本巨刃 +8 出现在 6 层、深渊之刃 +7 在 7 层，深层的反而更弱，
"只许更强"会把深渊之刃永久锁死。`test_weapon_table_is_monotonic_in_floor`
守住这条。

### 为什么存档用 JSON 而不是 pickle

- **安全**：`pickle.load` 会执行任意代码，存档一旦被替换就是后门；
- **可移植**：pickle 绑定"模块路径 + 类名"，重命名类老存档就报废；
- **可读**：JSON 能直接打开看、手工改，也能贴进实验报告。

### 读档后为什么行为完全一致

存档同时保存 `seed`（可复现整局）和 `getstate()` 的 625 个整数状态快照——
后者才能回到"当前这一刻"。读档后怪物 AI 的每一次随机判定都与存档时一致，
这条性质由 `test_rng_state_reproducible` 兜底。
